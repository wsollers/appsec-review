*Implemented means the code path exists, not full coverage. OWASP assessment is enabled by default across shipped profiles, with an explicit job-level opt-out; complete pinned catalogs do not imply more than the four supported narrow Python static procedures. Qualification is synthetic and never production-eligible. Live-model OWASP efficacy, runtime adapters, exploit confirmation and safety certification are not established. Direct CLI and Dagster share the enabled tagging/OWASP chain, not full graph parity: CI/post-build branches and standalone metadata sync retain their existing scope. PoC generation is shipped disabled; HTML/PDF report rendering is manual. Arrows summarize information dependencies, not exact scheduling.

02 — Remaining planned extensions

Not part of the current executable review path
The implemented PoC contract is compile-only: no pipeline executor, no observed trigger, no runtime result. Planned evidence feedback still requires re-resolution and deterministic adjudication. Missing remediation and chain stages are named report limitations, not clean results.
Discussion proposal · not implemented

A separate gate for critical-impact claims

Keep vulnerability confirmation separate from validation of the claimed critical impact. Before asserting that impact, require one coherent attack scenario, a source-linked entry-to-impact path, and an independent attempt to falsify it. If proof is incomplete, retain a visible verification backlog item rather than treating uncertainty as safety.
