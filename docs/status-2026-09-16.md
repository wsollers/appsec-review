## What we learned about the design (feed into design-v3.md)

- The memory-safety lane is **query pack → traced DB → IR verification**; SVF is reachability
  enrichment, not the substrate. Cheaper and measurable.
- Three of four Notepad++ CVEs were static non-taint properties (wrong table constant, table
  shorter than state count, constant-length read). Taint tools are the wrong instrument for them.
- Game code will defeat name-based rules; detection has to be IR-level and the **allocator
  inventory** has to be automatic or explicitly model-driven (unmeasured — yquake2 experiment).
- IR-level rules are correct only after handling: call-site bounds, getter summaries, opaque-
  pointer field 0, inheritance GEPs, canonical class identity, iterators. See validation/eastl.md.
- Process: the file-download loop cost more than any single bug. Everything now goes through
  GitHub; the laptop tree is no longer canonical — the remote is.

HAL5000 has **two separate, live Docker contexts** — confirmed live 2026-09-17, correcting this
section's earlier "not desktop-linux" note, which was wrong:

- WSL (`~/projects/appsec-review`, user `wsollers`): `docker context show` -> `default`,
  endpoint `unix:///var/run/docker.sock` — a native `dockerd` running inside the WSL2 distro
  itself, not Docker Desktop. Existing engagement images (e.g. `audit-native:local` built for the
  EASTL Tier A work) live here.
- Windows PowerShell (`F:\repos\appsec-review`): `docker context show` -> `desktop-linux`,
  endpoint `npipe:////./pipe/dockerDesktopLinuxEngine` — Docker Desktop's own engine.

These are two independent daemons with separate image stores — an image built under one context
is invisible to `docker images` run under the other. `desktop-linux` also appears in WSL's own
`docker context ls`, meaning Docker Desktop's WSL integration is already available for this
distro; it's just not the active context there.

To build in WSL (fast, native ext4 filesystem, per the WSL-local target workflow above) but land
the image somewhere Windows-side Docker Desktop tooling can see it, override the context for that
one invocation rather than permanently switching WSL's default (which would hide the
`default`-context images already built there):

```bash
DOCKER_CONTEXT=desktop-linux scripts/build-audit-images.sh
```

`scripts/build-audit-images.sh` / `scripts/Build-AuditImages.ps1` (added 2026-09-17) build every
pinned image (`audit-static`, `audit-native`, `audit-codeql`, `audit-iac`, `audit-container`,
`audit-report`) from one entrypoint; see their `--help`/comment-based help for the `-Context`/
`--context` override.
