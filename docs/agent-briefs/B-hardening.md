# Brief B: pipeline hardening (branch `hardening-b`) - LOCAL agent

Goal: remove the failure modes found in live runs so a full review completes without model repair rounds or whole-job failures caused by one bad unit. All items are independent; commit each separately.

## Items (in order)
### B1. Native SAST: one bad unit must not fail the job
Files: `native_sast.py`, `native_sast_adapters.py`, tests. Today a single unit that errors/times out/produces unparsable output fails the whole `02-native-sast` job. Change: a per-unit failure becomes a recorded gap (unit id, cause enum: TIMEOUT / TOOL_ERROR / PARSE_ERROR / OOM, no raw exception text from target output) and the job publishes `OK_WITH_GAPS` when at least one unit succeeded, `FAILED` only when the job itself is broken (all units failed, contract/schema violation, tampered attempt). Mirror the pattern already used by `dependency_b13_adapters.tool_gap` (license scan). Update the output schema (`schemas/native-sast*.json`) if a gap list is not yet expressible, and downstream consumers (`claim_ledger.normalize_leads` reads `units[].leads`; gaps must appear as coverage, not crash). Tests: one good unit + one failing unit => OK_WITH_GAPS, leads from the good unit kept; all failing => FAILED.

### B2. Build-plan unit mis-assignment
Files: `build_plan.py` (+ tests, `docs/processes/build-unit-classification.md` if it describes it). Symptom: a unit is assigned to the wrong build-plan unit (source files belonging to one build target attached to another). Reproduce with a fixture first (look at existing `tests/test_build_plan*.py` and the hello-autotools layout: autotools project with `src/` + `configure.ac`; multi-vuln has several `projects/<lang>/case-NNN` dirs). Fix deterministically in Python (path containment / longest-prefix ownership), not with model text. If you cannot reproduce it, write down what you checked and stop; do not guess.

### B3. OWASP validator: reduced reply schema + Python derive
Files: `owasp_validator_result.py`, `owasp_dispatch.py`, the owasp persona schema and prompt for `owasp-validator`, `schemas/owasp-assessment-evidence-citation.schema.json` (READ ONLY unless needed), tests `tests/test_owasp_*`. READ FIRST `owasp_validator_result.py` admission checks end to end, then the live evidence: about half of validator cells needed repair rounds because the model had to emit 16 required citation fields (citation_id, input_id, source_kind, artifact_path, artifact_sha256, accepted_pointer, locator, observed_fact, evidence_mode, freshness, covered_scope, limitations, canonical_dereference_id, test_context, derived_output_id, affirmative_contrary_evidence) and fabricated hashes / omitted properties. Change: the model replies with a REDUCED citation (input reference id or path as given in its brief, locator, observed_fact, evidence_mode, limitations, affirmative_contrary_evidence as applicable). Python derives everything else (citation_id, input_id, source_kind, artifact_path, artifact_sha256 by hashing the pinned file, accepted_pointer, freshness, covered_scope, canonical_dereference_id, test_context, derived_output_id) from the dispatched input set, and REJECTS a citation whose reference does not resolve to an input the cell was given (gap, not silent drop). The final admitted record must still validate against the unchanged full schema. Keep ADR-0013 style: derive module + independent validation. Do not weaken any admission check; add tests for: resolvable ref derives correct hash; unresolvable ref rejected; model-supplied hash ignored/overwritten; full-schema validation of the derived record. NOTE: do not deploy mid-run; this is a branch.
