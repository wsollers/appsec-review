# Continuation — EASTL testbed, native in WSL2, via the pipeline scripts

Supersedes the step-1 section of `2026-09-14-continuation-prompt.md`. Read `pipeline/README.md`
first. Everything runs from Ubuntu (WSL2) with sources on the WSL filesystem; Docker Desktop's
daemon is reached from the Linux `docker` CLI (no bridge penalty). The same commands run on
Zarathustra or a Linux server unchanged.

## 0. One-time: images and sanity (30 min, mostly build time)

```bash
git clone https://github.com/wsollers/appsec-review ~/projects/appsec-review && cd ~/projects/appsec-review
docker build -t audit-native:local images/audit-native                      # now also builds ir-facts + svf-taint into /opt
# CodeQL bundle: download on the host once (see images/audit-codeql/README.md), then
docker build -t audit-codeql-native:local -f images/audit-codeql/Dockerfile.native images/audit-codeql
images/audit-native/run.sh . - ./scratch -- /opt/scripts/smoke-test.sh                # 7 steps, all ok
docker run --rm audit-native:local bash -c 'ir-facts --help | head -1; svf-taint --help | head -1'
```
No MSVC headers are needed for anything in this prompt (all targets build natively for Linux).

## 1. EASTL: build to a compile DB, pregather, assemble (1–2 h)

```bash
git clone --depth 1 https://github.com/electronicarts/EASTL ~/targets/eastl && cd ~/targets/eastl && git submodule update --init
cmake -S . -B build -G Ninja -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_C_COMPILER=clang \
      -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DEASTL_BUILD_TESTS=ON -DEASTL_BUILD_BENCHMARK=OFF
cmake --build build -j$(nproc) 2>&1 | tail -2        # confirms the tree compiles with clang at all
cd ~/projects/appsec-review
pipeline/pregather.sh --target ~/targets/eastl --scratch ~/scratch/eastl --project eastl \
    --compile-db ~/targets/eastl/build/compile_commands.json --codeql --csa
pipeline/assemble.py --scratch ~/scratch/eastl --out ~/scratch/eastl/bundle.json
```
Expect: Tier A; one linked module per CMake target (EASTL lib, EASTLTest); `ir-facts-*.json`;
mythos SARIF (probably near-empty on EASTL's own code — that's fine, it's the baseline).
Record the numbers (TUs, link sizes, ir-facts counts, pack findings) in `validation/eastl.md`.
If clang++ from the host isn't LLVM 21 that is fine for the compile DB; the gate re-runs the
compiles with the image's clang, which is what produces the bitcode.

## 2. Container-agnostic IR rules (half day) — the point of using EASTL

Add to `ir-facts` (new `field_geps` section) and to `verify_candidate.py`:
- **data+size pair**: a GEP whose base pointer is loaded from struct field F and whose enclosing
  function also loads/compares an integer field G of the same struct that is stored from the
  allocation size at the allocation site → treat G as the bound for indexes through F. This is
  `eastl::vector` (`mpBegin`/`mpEnd`), `TArray` (`Data`/`ArrayNum`), and every hand-rolled
  container. Emit `bound_field` on the GEP fact; the verifier can then REFUTE when the index is
  dominated by a comparison against that field, VERIFY when it isn't.
- **fixed-buffer GEP**: GEP into an alloca'd or in-struct fixed array (`fixed_vector<T,N>` storage)
  with a non-constant index and no comparison against N — the stack/inline overflow class.
Validate on `EASTLTest`: every index in the test suite must REFUTE (tests are correct by
construction); count how many don't and why — that number is the rule's false-positive rate.

## 3. Seeded corpus (2 h) — write answers BEFORE running anything

`validation/eastl-seeded.md`: six small programs under `validation/eastl-seeded/` linking EASTL:
1. index from `read()`-derived byte into `eastl::fixed_vector<int, 16>` (unchecked)
2. length from input → `eastl::fixed_string<char, 32>::assign(ptr, n)` (unchecked)
3. arena (bump) allocator: pointer handed out, arena `reset()`, pointer used (reuse-after-reset)
4. pool: slot freed, stale index used to read the slot (pool reuse)
5. `count * sizeof(T)` from two input fields into `eastl::allocator_malloc` (overflow → small alloc → big copy)
6. `operator[]` used where the surrounding code's own `at()`-style check exists on other paths (guard present elsewhere, absent here)
Plus two benign twins (same shape, guarded) so discrimination is measured, not just detection.
Build them into the same compile DB (add as CMake targets), rerun pregather + assemble, score:
hits at the six sites, verdicts on the two twins, false positives elsewhere. This is the first
§19 corpus that looks like game code.

## 4. Allocator inventory experiment (half day) — see 2026-09-14-continuation-prompt.md step 2

yquake2 (C): `cmake -DCMAKE_C_COMPILER=clang -DCMAKE_EXPORT_COMPILE_COMMANDS=ON`, same pregather
path. Implement `ir-facts --alloc-inventory`; score against `Z_Malloc/Z_TagMalloc/Z_Free/
Hunk_Alloc/Hunk_Begin/Hunk_End` with names ignored. Write ADR-0007 with the verdict
(automatic / agent-confirmed / model file). Feed the inventory to the data+size rule (an
allocator's size argument is a "size field" source), SVF ExtAPI, and a CodeQL Models-as-Data file.

## 5. Then, in this order, each as its own prompt

- **Unreal**: cost side only (throughput, memory, human-verified FP rate on Core/Net modules;
  allocator inventory on `FMemStack`/`FMallocBinned`; `TArray` collapse). EULA: scratch only,
  nothing derived enters the repo. `UnrealBuildTool -Mode=GenerateClangDatabase` → `--compile-db`.
- **idTech4 (DOOM-3-BFG)**: C++ engine allocators (`Mem_Alloc`, `idBlockAlloc`, `idDynamicBlockAlloc`)
  for the inventory, mid-size scale point between yquake2 and Unreal.
- **Sealed holdout** (ioquake3, OpenTTD): freeze the pack (git tag), run blind, score against
  published CVEs → `validation/holdout-*.md`. Only then quote recall.

## What "done" looks like for this prompt

`validation/eastl.md` with numbers; `validation/eastl-seeded.md` with 6/6 + 2/2 scores and the
false-positive count on EASTLTest; the two IR rules in `ir-facts` + verifier with tests;
`allocator-inventory.json` for yquake2 with recall/precision and ADR-0007. Every run leaves a
`pregather-manifest.json` + `bundle.json`; no LLM was needed for any of it.

Standing rules: laptop/WSL tree is canonical; pin everything; container scripts are argv arrays;
host scripts have sh/ps1 twins; do not open ioquake3 or OpenTTD.
