\section{Operating model}
One engagement binds a target commit, permissions, source generation, build identity, tool pins and
offline reference snapshots. Every job publishes an immutable attempt and a current accepted
pointer. A successful process for one fixture is not evidence that the same check ran for another
target.

\begin{warning}
A job that did not run is a coverage gap, never ``no issues.'' Keep missing, stale, blocked and
unresolved states in the report.
\end{warning}

Target files are evidence data and cannot expand permission or change job policy.

\section{What the pipeline collects}
\subsection{Source and dependency evidence}
The source family runs language SAST including Go, Java and PHP; secrets, IaC and mobile checks;
container-image inventory; SBOM, licence and lifecycle analysis; and offline SCA matching. The SCA
workers bind exact Grype/OSV snapshot bytes and record snapshot age. Refresh happens outside the
engagement flow. Do not enable network access to bypass a stale snapshot.

\subsection{Build and binary evidence}
Build resolution discovers and replays build units in an isolated no-network worker. Imported
artifacts retain their build identity. Native outputs feed compiler-semantic SAST, LLVM IR,
Joern CPG/AST, tests, symbols, native-memory analysis and Checksec ELF hardening. Confirm that the
hardening result names the binary produced by the accepted native build.

\subsection{Search and cross-references}
Literal/full-text and LanceDB semantic projections answer text and concept queries. Joern and LLVM
IR projections answer structural queries over calls, symbols, types, flows and memory operations.
Every bounded record retains source location and build identity. Cross-references link partitions,
components, files, symbols, build units, binaries, dependencies, controls, threats, claims and
citations.

\section{Partition and assemble the review}
Discovery identifies independently buildable projects and operational surfaces. Component
characterization assigns stable component IDs, ownership, languages, trust boundaries, flows and
coverage. The full-review input assembler validates a supplied closed launch plan and emits
bounded family requests.

\begin{warning}
Automatic derivation of the complete launch plan from the component map, and automatic dispatch of
all emitted requests, remain integration gaps. Review and supply the closed plan explicitly.
\end{warning}

\section{Threat and standards branches}
\begin{description}[style=nextline,font=\sffamily\bfseries]
\item[L6A and L6B threat model] L6A creates the initial DFD and STRIDE hypotheses. L6B reconciles
them with accepted evidence, retaining conflict and model coverage. Both are executable and qualified.
\item[OWASP] T03--T14 routes ASVS/MASVS controls by component, performs bounded validation and
publishes deterministic pages, a status matrix, gaps and candidate routes. Automatic derivation of
trusted dispatch facts remains an operator gate.
\item[STIG/SRG] Selects and tailors platform controls into a separate validation worklist.
\item[Deployment hardening] Consumes the STIG/SRG worklist and deployment evidence. It reports
static configuration and exposure; it does not certify compliance.
\end{description}

\section{Claim rendezvous}
Candidate admission does not create findings. Red-team members propose attacks; blue-team members
try to refute or narrow them; independent verification alone may verify a claim. Deterministic merge
waits for every expected member, validates citations and ordering, and retains dissent. Evidence
quorum applies independence and evidence thresholds. Scoring consumes independently verified claims
only.

Never shrink the expected-member manifest after dispatch. Timeout, cancellation and blocked members
remain durable coverage gaps.

\section{Generate and review the draft}
\begin{terminal}
\cmd{python3 appsec-review-process/launch\_job.py -{}-run-id "\$RUN\_ID" -{}-job synthesis\_report -{}-wait}
\end{terminal}

The synthesis job publishes report JSON and Markdown, coverage appendix, trace index, publication
manifest, LaTeX presentation input, HTML and render manifests. Verify hashes,
citations, source/build identity, tool and control denominators, snapshot age, threat conflicts,
unresolved items and both claim-ledger heads.

\begin{danger}
The expected status is \mono{DRAFT\_EVIDENCE\_BACKED}, \mono{final=false}, and
\mono{human\_signoff=false}. Do not relabel it FINAL.
\end{danger}

\section{Current completion gates}
The nominal workers and retained qualifications exist. Final publication still requires:
\begin{enumerate}
\item automatic launch-plan derivation and request dispatch from components;
\item automatic derivation of OWASP trusted dispatch facts;
\item one retained report produced from the complete real accepted upstream chain; and
\item explicit human publication authorization.
\end{enumerate}
