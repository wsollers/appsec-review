[P1] Reject an accepted-pointer rollback before extending the request ledger

`_accepted_state()` validates the referenced attempt and its ledger, but it neither binds the accepted pointer's `run_id`, `job_id`, `scope_id`, and `request_id` to the current request nor requires the pointer to identify the newest attempt in `latest.json` (`appsec-review-process/owasp_dynamic_requests.py`, around lines 404-439). An older, otherwise valid `accepted.json` can therefore be restored after a newer state was published, and `publish()` will accept a second transition from that stale state, creating an alternate history at the same next version. Bind all pointer identity fields and require the accepted attempt to be the current/newest accepted head (or enforce an equivalent monotonic head invariant) before deriving a transition. Add a regression that publishes two states, rolls `accepted.json` back to the first, and proves a new branch from the stale state is rejected.
